# `srcs/Client.cpp` のドキュメント

このファイルは、IRCサーバーに接続された単一のユーザーを表す`Client`クラスを実装しています。

## 責務

- **状態管理:**
    - クライアントのファイルディスクリプタ（`_fd`）を保存します。
    - 認証状態（`_isAuthenticated`, `_hasPassword`, `_hasNick`, `_hasUser`）を追跡します。クライアントは、これらすべてがtrueの場合にのみ、完全に登録され認証されたと見なされます。
    - ユーザー情報（ニックネーム `_nickname`、ユーザー名 `_username`、ホスト名 `_hostname`、リアルネーム `_realname`）を保持します。
- **バッファ管理:**
    - `_recvBuffer`: クライアントから受信したデータを、完全なメッセージ（`\r\n`で終わる）が受信されるまでバッファリングする文字列です。
    - `_sendBuffer`: クライアントに送信されるメッセージをキューに入れる文字列です。`send()`呼び出しが一度にメッセージ全体を送信できない場合があるため、これはノンブロッキングI/Oにとって重要です。
- **メッセージハンドリング:**
    - `appendRecvBuffer()`: 新たに受信したデータを`_recvBuffer`に追加します。
    - `hasCompleteMessage()`: `_recvBuffer`に1つ以上の完全なメッセージ（つまり`\r\n`を含む）が含まれているかどうかを確認します。
    - `extractMessage()`: 完全なメッセージが存在する場合、このメソッドは`_recvBuffer`から最初のメッセージを抽出し、バッファから削除して、処理のために返します。
- **ユーティリティ:**
    - `getPrefix()`: クライアントのプレフィックス文字列（例：`nickname!username@hostname`）を構築します。これは、多くのIRCコマンドの返信やブロードキャストで使用されます。

## クライアントのライフサイクル

1.  新しいTCP接続が受け入れられると、`Server::handleNewConnection()`で`Client`オブジェクトが作成されます。クライアントのファイルディスクリプタで初期化されます。
2.  サーバーはデータを受信し、クライアントの`_recvBuffer`に追加します。
3.  サーバーは継続的に`hasCompleteMessage()`をチェックします。
4.  完全なメッセージが利用可能になると、`extractMessage()`が呼び出され、メッセージが処理されます。
5.  クライアントは`PASS`、`NICK`、`USER`コマンドを送信します。`CommandHandler`内の対応するハンドラが、クライアントの状態（`_hasPassword`、`_hasNick`など）を更新します。
6.  必要なすべての登録手順が完了すると、`_isAuthenticated`が`true`に設定されます。
7.  クライアントに送信されるメッセージは、`Server::sendToClient()`を介して`_sendBuffer`にキューイングされます。
8.  サーバーのメインループは、クライアントのソケットが書き込み可能になったときに`_sendBuffer`からデータを送信します。
9.  クライアントが切断すると、`Client`オブジェクトは`Server::removeClient()`で削除されます。
