# `srcs/commands/` のドキュメント

このディレクトリには、`CommandHandler`クラスのさまざまな`handle...()`メソッドの実装が含まれています。各ファイルは関連するIRCコマンドをグループ化しています。

---

## `auth.cpp`

クライアントの認証と登録に関連するコマンドを処理します。

- **`handlePass(Client* client, const Message& msg)`**
    - クライアントが既に登録済みかどうかを確認します。
    - パスワードが提供されたことを検証します。
    - 提供されたパスワードをサーバーのパスワードと比較します。
    - 正しい場合、クライアントの`_hasPassword`フラグを`true`に設定します。
    - フラグを設定した後、クライアントが完全に認証準備ができたかを確認し、そうであればウェルカムメッセージを送信します。

- **`handleNick(Client* client, const Message& msg)`**
    - ニックネームが提供されたことを検証します。
    - `isValidNickname()`を使用して有効な構文か確認します。
    - ニックネームが他のクライアントによって既に使用されていないか確認します。
    - 有効で利用可能な場合、クライアントのニックネームを設定します。
    - クライアントが既に認証済みの場合、関連するチャンネルにニックネームの変更をブロードキャストします。
    - 登録完了の確認をします。

- **`handleUser(Client* client, const Message& msg)`**
    - クライアントが既に登録済みかどうかを確認します。
    - 必要なすべてのパラメータ（`username`、`hostname`、`servername`、`realname`）が提供されたことを検証します。
    - クライアントのユーザー名とリアルネームを設定します。（注意：この実装では`hostname`と`servername`は無視されます）。
    - `_hasUser`フラグを`true`に設定し、登録完了の確認をします。

## `channel.cpp`

チャンネルへの参加と退出に関するコマンドを処理します。

- **`handleJoin(Client* client, const Message& msg)`**
    - パラメータとチャンネル名の構文を検証します。
    - `Channel`オブジェクトを取得または作成します。
    - 一連のチェックを実行します：
        - ユーザーは既にチャンネルにいますか？
        - チャンネルは招待制（`+i`）ですか？
        - チャンネルは満員（`+l`）ですか？
        - 提供されたキーは正しい（`+k`）ですか？
    - すべてのチェックが通れば、クライアントをチャンネルのメンバーリストに追加します。
    - チャンネルが新しく作成された場合、クライアントはチャンネルオペレーターになります。
    - `JOIN`メッセージをすべてのメンバーにブロードキャストします。
    - チャンネルのトピックとメンバーリスト（`NAMES`）を参加したクライアントに送信します。

- **`handlePart(Client* client, const Message& msg)`**
    - パラメータを検証します。
    - 指定された`Channel`を見つけます。
    - ユーザーが実際にチャンネルのメンバーであるか確認します。
    - `PART`メッセージをすべてのメンバーにブロードキャストします。
    - クライアントをチャンネルから削除します。
    - チャンネルが空になった場合、サーバーによって削除されます。

## `message.cpp`

メッセージ送信に関するコマンドを処理します。

- **`handlePrivmsg(Client* client, const Message& msg)`**
    - ユーザーやチャンネルにメッセージを送信するための主要なコマンドです。
    - 受信者とメッセージテキストの存在を確認します。
    - **ターゲットがチャンネル（`#`または`&`）の場合:**
        - チャンネルが存在し、ユーザーがメンバーであるかを確認します。
        - 送信者を除くすべてのチャンネルメンバーにメッセージをブロードキャストします。
    - **ターゲットがユーザーの場合:**
        - ターゲットユーザーが存在するか確認します。
        - そのユーザーに直接メッセージを送信します。
    - 何か問題が発生した場合は、適切なエラー応答を送信します。

- **`handleNotice(Client* client, const Message& msg)`**
    - 機能的には`PRIVMSG`と非常に似ています。
    - 主な違いは、`NOTICE`は自動的なエラー応答（例：`ERR_NOSUCHNICK`、`ERR_CANNOTSENDTOCHAN`）を送信してはならないことです。送信者の視点からは静かに失敗します。これは、自動化されたクライアント間のメッセージループを防ぐためです。

## `operator.cpp`

通常、チャンネルオペレーターに制限されているコマンドを処理します。

- **`handleKick(Client* client, const Message& msg)`**
    - チャンネルからユーザーをキックします。
    - チェック項目：
        - 送信者はチャンネルのメンバーですか？
        - 送信者はチャンネルオペレーターですか？
        - ターゲットユーザーは実際にチャンネルにいますか？
    - チェックが通れば、`KICK`メッセージをブロードキャストし、ターゲットユーザーをチャンネルから削除します。

- **`handleInvite(Client* client, const Message& msg)`**
    - ユーザーをチャンネルに招待します。
    - チェック項目：
        - 送信者は招待制（`+i`）チャンネルのチャンネルオペレーターですか？（注意：この実装では、チャンネルが`+i`でなくてもオペレーター権限が必要です）。
        - ターゲットユーザーはまだチャンネルにいませんか？
    - ターゲットのニックネームをチャンネルの招待リストに追加します。
    - ターゲットユーザーに`INVITE`通知を送信し、送信者に確認応答を送ります。

- **`handleTopic(Client* client, const Message& msg)`**
    - チャンネルのトピックを表示または変更します。
    - **新しいトピックが提供されない場合:** 現在のトピックまたは「トピックなし」の応答を返します。
    - **新しいトピックが提供された場合:**
        - チャンネルがトピック制限（`+t`）であり、送信者がチャンネルオペレーターであるかを確認します。
        - 許可されていれば、新しいトピックを設定し、変更をすべてのメンバーにブロードキャストします。

- **`handleMode(Client* client, const Message& msg)`**
    - チャンネルモードを表示または変更します。
    - **モード文字列が提供されない場合:** チャンネルの現在のモード（`+i`、`+t`、`+k`、`+l`）を返します。
    - **モード文字列が提供された場合（例：`+o-i`）:**
        - 送信者がチャンネルオペレーターであるかを確認します。
        - モード文字列を解析してモードを追加（`+`）または削除（`-`）します。
        - パラメータを必要とするモード（例：`+o <nick>`、`+l <limit>`、`+k <key>`）を処理します。
        - モードの変更をすべてのチャンネルメンバーにブロードキャストします。
