# `srcs/CommandHandler.cpp` のドキュメント

このファイルは、クライアントから受信したすべてのIRCコマンドの中央ルーターとして機能する`CommandHandler`クラスを実装しています。

## 責務

- **コマンドルーティング:**
    - 主要なメソッドは`execute(Client* client, const Message& msg)`です。
    - `client`と解析済みの`Message`オブジェクトを受け取ります。
    - メッセージからコマンドを読み取り、大文字小文字を区別しないマッチングのために大文字に変換し、適切な`handle...()`関数を呼び出します。
- **認証チェック:**
    - 重要なチェックを実行します：クライアントがまだ認証されていない場合（`!client->isAuthenticated()`）、ほとんどのコマンドを拒否し、`ERR_NOTREGISTERED`応答を送信します。
    - 完全な登録前に許可されるのは、特定のコマンドセット（`PASS`、`NICK`、`USER`、`PING`、`QUIT`）のみです。
- **不明なコマンドの処理:**
    - コマンドが既知のどのコマンドとも一致しない場合、`ERR_UNKNOWNCOMMAND`応答をクライアントに送信します。
- **ヘルパー関数:**
    - `isValidNickname()`: ニックネームの構文（長さ、許可される文字）を検証するロジックを含みます。
    - `isValidChannelName()`: チャンネル名の構文（`&`または`#`で始まる、最大長、不正な文字がない）を検証するロジックを含みます。

## コマンド処理フロー

1.  `Server::processClientMessage()`が`_commandHandler->execute()`を呼び出します。
2.  `execute()`は`Message`オブジェクトからコマンドを取得します。
3.  大きな`if-else if`ブロックが、コマンド文字列に基づいてどのハンドラ関数を呼び出すかを決定します。
4.  ほとんどのハンドラにルーティングする前に、`client->isAuthenticated()`をチェックします。
5.  対応する`handle...()`関数が実行され、そのコマンドの特定のロジックが含まれています。
6.  ハンドラ関数は`_server`を使用して、クライアントに応答を返したり、チャンネルにメッセージをブロードキャストしたりします。

## コマンドグループ

`execute`メソッドは、さまざまなカテゴリのコマンドを処理するように構成されています：

- **認証前コマンド:** `PASS`、`NICK`、`USER`は登録用です。`PING`と`QUIT`は常に利用可能です。
- **チャンネルコマンド:** `JOIN`、`PART`。
- **メッセージコマンド:** `PRIVMSG`、`NOTICE`。
- **オペレーターコマンド:** `KICK`、`INVITE`、`TOPIC`、`MODE`。これらのコマンドは通常、ユーザーがチャンネル内でオペレーター権限を持っている必要があります。

これらの`handle...()`関数の実際の実装は、コードを整理するために`srcs/commands/`ディレクトリの複数のファイルに分割されています。`CommandHandler.cpp`自体は、`execute`ディスパッチャと`PING`や`QUIT`のような単純なコマンドのいくつかのハンドラのみを含んでいます。
